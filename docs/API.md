# CareerSync AI API

The active API is FastAPI under `/api/v1`. OpenAPI is generated by the running
application and response errors use an `error.code`, `error.message`, and
`request_id` envelope.

## Implemented foundation

- `GET /health`
- `POST /api/v1/auth/register`
- `POST /api/v1/auth/login`
- `POST /api/v1/auth/refresh`
- `POST /api/v1/auth/logout`
- `GET /api/v1/auth/me`
- `GET/POST /api/v1/jobs`
- `GET/PATCH /api/v1/jobs/{job_id}`
- `POST /api/v1/jobs/{job_id}/resumes`
- `POST /api/v1/profile/resumes`
- `POST /api/v1/jobs/{job_id}/applications`
- `GET /api/v1/applications`
- `PATCH /api/v1/applications/{application_id}/status`
- `POST /api/v1/applications/{application_id}/notes`

Candidate leaderboard, evaluation retrieval, processing telemetry, and full
profile endpoints are the next integration slice. The API intentionally does
not expose ORM objects directly; Pydantic contracts define the public shape.

## Authentication and authorization

Access tokens are short-lived JWTs. Refresh sessions are rotated and revocable.
Refresh tokens are HttpOnly cookies. Every protected endpoint derives ownership
from the authenticated principal and database relationships; caller-supplied
owner IDs are not trusted.

Older Express/MongoDB endpoint descriptions are historical and are not a
supported implementation target.
